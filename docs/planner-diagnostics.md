# 规划器决策诊断

默认不记录决策文件。调试 planner 时，可在启动进程前设置环境变量：

```powershell
$env:KAA_PLANNER_TRACE_DIR = 'C:\path\to\evidence'
```

每场课程/考试产生独立的 `decisions-<随机ID>.jsonl`，最多记录256次决策及各自反馈：

- `decision`：决策状态、费用、强化等级、效果与触发条件ID、候选评价和最终选择。
- `feedback`：通过同一 `sequence` 对应上一条决策，记录是否观察到出牌生效及课程差值变化。

状态包含推断出的牌堆、全力点和姿态，**不是游戏真实状态**。没有后续决策时，最后一次出牌可能没有反馈记录。
候选列表是资源过滤和末段调整之后、足量CLEAR筛选之前的候选，并非所有识别到的手牌。
记录不额外截图或点击，写文件失败不阻止出牌，但开启后会有少量文件写入延迟。

独立的 `KAA_PLAY_EVIDENCE_DIR` 可捕获付费出牌后无可观察变化的三帧截图；它会额外获取出牌后截图，因此可能影响诊断时的时序。
`KAA_PRODUCE_EVIDENCE_DIR` 用于课程结果截图。这三个开关互相独立，均不改变保存的培育方案。
文件保存在指定目录，不自动上传。验证完清除环境变量即可停止记录。

## 姿态观察边界

强气火焰图标仅在顶部姿态栏识别，匹配后可以校正漏记的强气姿态，并用于输出和费用计算。
图标存在不证明超强气等级；已有超强气推断不会因此降级，普通推断则只校正为基础强气。
校正不增加热意或姿态切换次数，暂不通过图标缺失取消强气。
全力本身是独立指针，存在时不叠加温存/强气的倍率和费用；全力解除前，卡牌的指针变更不生效，其他效果继续处理。
全力HUD优先于强气图标校正，清除残留指针，不凭空补发热意、切换计数或出牌次数。
温存和热意图标的直接观察仍未启用，需要分别校准正反样本。

## 全力点观察边界

顶部灰色星标使用独立灰度匹配，数字经五种图像处理结果投票：至少三票一致，且不同数字的票数少于两票。
只接受完整的一至三位数字，包括零；数字不可读或图标未匹配时，不产生全力点观察，也不将推断值清零。
可信读数校正当前全力点及待触发状态，用于判断点数阈值和继续积攒的收益；不修改累计获得点数，不凭点数直接增加出牌次数或判定全力已经发动。
这属于同帧多种处理方式的一致性校验，不是跨帧确认。当前真实截图回归覆盖5、6、8点；零点和阈值附近的两位数仍需补充实机样本。

## 未确认出牌与回合缺读

请求出牌后的记忆为推测，直到下一帧反馈提供正证据。证据不足时撤销推测并重新应用当前HUD观察，不将请求判成失败，也不累计不可观察的姿态切换、增益或出牌次数。代价是成功但始终不可观察的效果仍保持未知。同名牌补回可通过同回合的资源变化或两次已知原始HUD数值变化确认；移动弹窗保留原有正证据。资源/HUD变化只能确认存在可观察变化，不能证明全部预测效果正确或直接归因单卡产分。

`remaining_turns_known=false` 表示HUD缺读或跳变尚未通过确认；此时 `remaining_turns=1` 是保守评价窗口，不是实际剩余回合。记忆中的历史计数仍用于后续可靠读数恢复，初次默认7不触发真实回合衰减。回合条件返回UNKNOWN。这个窗口可能低估长课程准备收益，需要实机检验，不能当作未知状态的最优策略。官方评价表索引与实际回合数分别说明。

反馈新增 `after_state`，来自产生反馈的同一次读取上下文，在撤销推测之前记录；各读取器会分别截图，不能视为整组数据共用一张图片；其中仍有推断字段，应优先使用 `observed_effect_values` 等原始观察字段。旧记录没有此字段时只能关联下一次决策，需保留这一来源差异。

## 离线样本筛选入口

运行 `python -m kaa.tasks.produce.new.play_cards.planner.replay <trace目录> --output <报告.json> --run-id <培育轮次> --scheme <方案> --code-version <当时版本>`，报告保留源文件、sequence、版本/轮次/方案、前后状态、差值与筛除原因。版本与方案由操作者提供，旧记录无法自行证明这些信息。

筛除跨回合、目标未知或切换、未确认出牌、移动弹窗、缺少最终反馈和没有正产分预测的样本。剩余 `manual_review_candidate` 仍需人工核对OCR、成长、附魔和事件顺序，误差仅用于诊断，不是已确认单卡标签。工具支持旧trace关联下一次决策，标记为 `next_decision_legacy`；新记录优先使用反馈帧。按完整培育轮次划分校准/留出集，不能逐手随机拆分。本入口尚不重建完整牌库执行反事实排序，也不自动调权。

2026-10-03补充：首次可靠基线建立之前，待确认的OCR跳变也不会衰减增益。生产状态新增 `observed_remaining_turns`、`observed_hp`、`observed_genki` 保存校正前读数，便于区分缺读、拒绝跳变和前缀纠正；这些原始数值仍可能OCR误读。旧trace没有对应字段时保持缺失，不能补造。


## 共享费用与静态效果诊断

评价、支付检查和两步模拟共用 `costs.play_cost`，沿用旧模拟器的整数round规则。尚未验证游戏的半整数舍入，也未覆盖减耗/免耗等持续修饰；trace的 `modeled_payment.model=stance_only_existing_rounding` 明确此边界。启发式费用惩罚现在使用相同整数费用，奇数费用温存卡可能发生排序变化。

全力点、集中、好印象、干劲、好调、绝好调六类特殊消耗另行检查。仅在原始数值与校正后的余额一致时证明可支付/不可支付，缺读或校正待确认保持未知，不拿推断默认零拒绝首手。未知特殊费用不作为确定可支付的后续组合。模拟继承已确认余额的支付/建模效果结果；模拟内部的观察数值是用于下一步支付的假设余额，不能当作新的HUD实测。好调/绝好调消耗会扣持续回合；消费全力点也重算待触发阈值，累计获得点数不扣减。

候选新增 `cost_type`、`cost_value`、`modeled_payment` 和静态 `customize_ids`；效果保留参数、次数、回合、链式效果、成长、搜索与附魔ID，顺序沿用读取的卡牌效果列表。这些来自本地静态卡数据，不代表已观察到局内成长、自定义增量、附魔触发或真实结算顺序。旧schema 1记录缺字段仍可筛选；新字段不补造旧记录。没有新增截图或设备操作。


## 实测后的观察修复（2026-10-03）

强化读取新增浅蓝色标题后缀识别，保留原有颜色通道的结果。红色徽标缺失时，仅在右侧标题完全露出（无下一张牌，或字母中心相距至少200px）才使用后缀；拥挤手牌的遮挡仍可能回落到基础版，尚未显式建模强化等级未知。真实回放包含オーバードライブ++被基础版识别、费用5而画面费用3的案例。此修复改善静态强化等级，不能替代局内成长/自定义效果模型。

元气二值图和原图都缺读时，只接受另一现有OCR引擎置信度至少0.98的单个字面“0”。低置信度、非零、字母O和引擎异常仍保持未知，不把“bo”直接改写成数字。回退只用于原有启用fallback_raw的读取路径，会增加缺读场景的OCR耗时。

planner的排名考试改用圆形回合徽标专用区域，提取白色数字并要求两个OCR引擎同值、置信度至少0.98，冲突或缺失返回未知。课程仍用原有两区域逻辑，旧专家策略也未切换到新考试读数。保存图片验证覆盖1/12，其他已保存考试输入另作离线回放；16be7f3后续完整实机已覆盖12/1与元气0，但最终考试仍有2次回合未知，不能宣称全部可读。

本轮仓库外验证脚本保存各读取器实际图片、区域、原始数字与来源hash，证实一手内部可能跨帧；保留全图HUD/手牌和数值裁剪，未增加设备截图，但复制/编码/文件写入有时序开销。手牌记录时间是写入时间，不是原始采集时间。脚本属于验证工具，生产trace仍未自动绑定这些图片。


HP专用读取对900—999的疑似心形边缘前缀做同一裁剪图的独立OCR校验：仅接受置信度至少0.98的原值或去除开头9后的精确后缀；冲突、低置信度或引擎异常返回未知。其他数值不触发此回退，独立引擎确认的三位HP保留原值。它不依赖上一手资源，也不设置全局HP上限；首手35误读935的真实输入已纳入回归。该补修在16be7f3实机结束后加入，不归因于此前整轮成绩。


1ad484e后续实测发现其他心形前缀：画面8可读28、9可读79、7可读57；仅检查900—999不足。HP读取现在对所有候选执行同图独立校验，只接受置信度至少0.98的单个字面同值，保留已有9xx精确后缀恢复；其他冲突/低置信度/异常为未知，不根据任意尾数纠正余额。已确认的合法大值仍可保留。会增加每次HP读取的OCR开销，并使部分原可读但未获独立确认的输入未知；没有新增设备截图。HP与元气等旧历史校正仍是额外保守边界，双OCR一致也不等于真值保证。


## 战斗结束的最后一次请求

课程或考试正常满足结束条件时，战斗循环通知策略结束。planner将仍待观察的最后请求记为feedback：status=unconfirmed、evidence=battle_ended_without_observation、after_state=null，并清理pending。它不读取结束画面的战斗HUD，不根据课程成绩确认该牌成功，也不补造产分或资源变化；重复结束通知不重复记录，其他策略的默认结束通知为空操作。异常退出仍可能缺少这条正常结束记录。

回放将该样本明确标记battle_end_unobserved并筛除，不借后续决策作为终局状态。统计时区分“实际反馈状态帧”与“终局未观察记录”；即使最后一手已成对记录，最后一手真实产分/资源证据仍未补齐。


f7bb9bf实测中，16次HP未知包含3次29/9高置信度冲突，以及11次真实0、一次4、一次15的独立OCR低置信度。后续补修仅对原图未获得高置信度单个读数的情况，提取同图近白像素（所有通道>245、通道差<12）再次交给独立OCR；仍要求置信度至少0.98、字面同值或既有9xx精确后缀。原图的高置信度冲突直接保持未知，不能被掩码覆盖，异常同样未知。真实0/4/15素材纳入回归，不降低置信度门槛；回退会增加低置信度场景的OCR开销，没有额外设备截图。它在实机结束后加入，尚需后续完整实机验证。


f3707e3实机发现元气11辅助OCR读117，而仅靠历史值的末两位纠错反而写成17。同图独立OCR读11、置信度0.9994。后续补修对三位元气原始读数做同图独立确认：高置信度同值保留真实三位数，高置信度两位连续子串接受并记录校验日志，缺读/冲突保持未知；策略层不再根据历史元气截末两位。普通一两位和零值回退不变。`observed_genki`记录页面最终读数，原始辅助117需从校验日志或验证输入图追溯；补修尚待实机。
